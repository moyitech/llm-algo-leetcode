# Group 2.6: Inference Execution and Generation Acceleration | 2.6：推理执行与生成加速

模型生成得慢，先拆成两个问题：一次前向能否更高效，一轮前向能否推进更多 token（词元）。前者要看 attention 中间量、融合与实际执行路径；后者要理解采样、草稿生成和验证。本组用 8 节练习把两条路径连起来。

初学可跟随下面的顺序，遇到具体问题也能直接跳到速查卡。连续讲解见专题 [02 Prefill](../topic_discussion/inference_optimization/02_prefill_and_attention_kernel.md)和 [03 解码策略](../topic_discussion/inference_optimization/03_decoding_strategies.md)。

## 学习路径

先读 **20 → INF-EXECUTION-DISPATCH**：从避免保存完整分数矩阵，到判断优化候选能否被 backend（执行后端）支持。调用高效 API 后，还要确认实际路径与成本。

再读 **21 → 23**：先知道单步如何从 logits（词表分数）选 token，再理解 draft（草稿）为何必须经过 target（目标模型）验证与修正。

然后按兴趣选择 **35 / INF-EAGLE / INF-PARALLEL-DRAFTING**，分别了解模型内预测模块、target 特征和并行草稿。它们是不同的候选来源。最后读 **INF-PROPOSAL**，把接受情况和额外成本放在一起决定预算。

## 去哪里验证

Step 1–4 默认可在 CPU 上运行。20 的 GPU 部分比较显式 attention 与 SDPA；执行分派比较 eager 与 compile；23 和动态预算比较真实模型生成；35 与 EAGLE 的历史记录还包括未成功的 backend 尝试或配对条件检查，不能当成已取得加速结果。

运行前先读[环境 Quickstart](../topic_discussion/inference_optimization/quickstart.md)和[实验资产表](../topic_discussion/inference_optimization/experiment_assets.md)。CPU 通过只能验证练习逻辑，合成块的局部收益也不能直接代表在线服务。

真实模型与 backend 对照进入 [68 投机解码基准](./68_Speculative_Decoding_Benchmark.md)。涉及多请求 KV 状态、动态批次和阶段调度时继续 [2.7 组](./2_7.md)；按问题查找可用[判断手册](../topic_discussion/inference_optimization/casebook.md#机制速查索引)。
